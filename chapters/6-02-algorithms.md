# 6-02 算法：软件怎么"算"

> 上一章把数据「摆」好了。这一章解决「算」：**怎么在一堆数里找到你要的、怎么把乱序排整齐、怎么把信息锁起来、怎么知道一个方法到底快不快。** 这一章你会反复撞见前面学过的老朋友——对数（2-03）、质数（1-04）、数量级（1-02 / 5-06）——它们在这里被翻译成「机器能一步步执行的步骤」。算法，就是连接「数学想法」和「机器动作」的那座桥。

---

## 2.1 算法是什么：解决一类问题的步骤清单

**算法（algorithm）= 一份「怎么做」的步骤清单。** 它有三个要素：

1. **输入**：喂给它什么（比如一堆数）。
2. **步骤**：每一步都无歧义、可执行、有限步内做完。
3. **输出**：最后给出什么（比如排好序的数）。

**类比**：菜谱。「做红烧肉」的菜谱，就是一道算法——输入是食材，步骤是「切块→焯水→炒糖色→炖」，输出是成品。菜谱不能写「加适量盐」这种模糊话（机器不懂「适量」），必须写「加 5 克盐」。**算法和菜谱一样：每一步都必须明确到机器能照着做。**

注意两个容易混的词：**「算法」是思路，「程序」是思路的实现。** 同样是「把数排整齐」这个思路（算法），可以用不同语言、不同写法（程序）来实现。**先有思路，再有代码**——这一章讲的是思路，伪代码只是帮你看清思路长什么样。

## 2.2 为什么算法是数学：全书的伏笔在这里兑现

算法不是「计算机系自己的手艺」，它骨子里全是数学。把前几部分的账收一下：

- **二分查找 = 对数**（2-03）：每次砍半，log₂(n) 步就能找完 n 个。
- **加密 = 质数 + 模运算**（1-04）：乘起来容易、拆回去难，靠的是质数的「唯一分解」。
- **复杂度 = 数量级**（1-02 的「无穷大小」、5-06 的「估算」）：不看精确时间，看「规模翻倍时怎么涨」。

**所以「算法」这个词，本质是「把数学想法，翻译成机器能执行的一串动作」。** 一个算法好不好，追到底，是它背后的数学好不好——这就是为什么本书一直把「数学」当作「计算机的底层语言」。

## 2.3 搜索算法：怎么在一堆数里找到它

问题：给你 n 个排好序的数，找出里面有没有「42」。

**① 线性搜索（一个一个找）—— O(n)**
从第一个数开始，挨个比，直到找到或看完。最坏要找 n 次。

```
从头到尾：
  对每个数 x：
    如果 x == 42：找到，停
没找到 → 报告「没有」
```

**② 二分搜索（每次砍半）—— O(log n)**
因为数是排好序的，每次问「中间那个」：比 42 大，就去左半边找；比 42 小，就去右半边找。**每次砍掉一半。**

```
左 = 0，右 = n-1
当 左 <= 右：
  中 = (左 + 右) / 2
  如果 arr[中] == 42：找到，停
  如果 arr[中] > 42：右 = 中 - 1     （去左半边）
  否则：              左 = 中 + 1     （去右半边）
没找到 → 报告「没有」
```

**差距有多大？** 1 亿个数，线性要最多 1 亿次；二分只要 **约 27 次**（log₂(10⁸)≈27）。**这就是「对数」的威力**——它把「搜索」从「线性」压成了「超快」。

## 2.4 排序算法：把乱的排整齐

问题：给你一堆乱序的数，从小到大排好。

**① 冒泡排序（最直观）—— O(n²)**
从头走到尾，相邻两个比较，大的往后「冒」；走一遍，最大的沉到末尾；再走一遍，第二大的沉到位……像气泡一个个冒出来。

```
重复 n 次：
  从头走到尾：
    如果 前一个 > 后一个：交换它俩
```

它简单到「一眼就懂」，但很慢：n 个数，最坏要比 n² 次。

**② 快速排序（分而治之）—— O(n log n)**
挑一个「基准」，把小的放它左边、大的放它右边，然后**对左右两半，各自再用同样的办法排**。

```
如果只有 0 或 1 个数：直接返回
挑一个基准 pivot
把比 pivot 小的放左边，比 pivot 大的放右边
对左边用同样的办法排
对右边用同样的办法排
```

它的精髓叫**「分而治之」**：一个大问题，拆成两个小问题，各自解决，再合起来。**这个思想你其实早见过了**——3-04 的「割补」（把陌生形状割成会算的形状）、2-05 的「消元」（把两个未知数削成一个）、3-07 的「降维」（把三维拍扁成二维），都是「分而治之」的同胞。**数学里的「分而治之」，在算法里就叫「递归地拆小」。**

## 2.5 递归：函数调用自己

很多算法「自己解决一个缩小版的自己」，这就是**递归（recursion）**。

**① 阶乘**（回收 0-02 的 `!`）：n! = n × (n−1)!。要算 5!，就先算 4!；要算 4!，就先算 3!……直到 1! = 1 这个「地基」，再一层层往回乘。

```
算 factorial(n)：
  如果 n == 1：返回 1            （基线：出口）
  否则：返回 n × factorial(n-1)  （递归：缩小一号）
```

**② 斐波那契**（回收 1-05.3）：fib(n) = fib(n−1) + fib(n−2)，一路拆到 fib(1)=fib(2)=1。

递归的**灵魂是「基线」**——必须有个「不用再递归、直接给答案」的出口，否则它会无限地调用自己，永远停不下来。**这个「停不下来」不是小 bug，它正是下一节 2.8 要讲的「停机问题」的日常版**：一个算法会不会停，有时候真的没法提前知道。

**类比**：套娃。每个娃娃里套一个更小的娃娃，直到最里面那个实心的「地基」娃娃，再一个个套回去。

## 2.6 加密算法：把信息锁起来

回访 1-04.5 的 RSA，现在看它的「算法」长什么样：

- **两个大质数** p、q → 算 n = p×q。公开 n，保密 p、q。
- **加密**：把信息 m 变成密文 c，用一条模运算：`c = m^e mod n`（mod 是「取余数」，回收 5-06 生活章的「模 7 算星期几」）。
- **解密**：知道 p、q 的人，能算出「密钥」，把 c 还原成 m；不知道的人，必须先「分解 n」，而分解大数难如登天。

```
加密：c = m^e mod n      （公开 n，人人都能加密）
解密：m = c^d mod n      （只有知道 p、q 的人能算出 d）
攻击：把 n 分解回 p×q    （目前没有快速算法，≈算不完）
```

**它的安全，不靠「锁有多精巧」，靠「拆锁有多难」。** 乘起来一瞬间，拆回去要算到天荒地老——这道「易去难回」的单向门，正是 1-04 那句「没用的质数研究，几十年后守住了互联网」的兑现。

顺带一句：还有一个更日常的「加密亲戚」——**哈希指纹**（上一章 6-01.6 的 hash）。它把「任意长的文件」压成一个固定长度的「指纹」，文件改一个字节，指纹就全变。**网站存密码存的是「指纹」而不是密码本身**——这样即使数据库被偷，也偷不到你的原密码。

## 2.7 算法复杂度：怎么判断一个算法快不快

计算机科学家用**大 O 记号**，衡量「算法耗时随规模怎么涨」。**不看精确秒数，看「数据翻倍时，时间怎么变」**（回收 5-06 的「估算」、1-02 的「数量级」）：

| 记号 | 名称 | 含义 | 例子 |
|---|---|---|---|
| O(1) | 常数 | 不管多大，一步 | 按号取格子（数组） |
| O(log n) | 对数 | 每步砍半 | 二分搜索 |
| O(n) | 线性 | 规模翻倍，时间翻倍 | 线性搜索 |
| O(n²) | 平方 | 规模翻倍，时间 4 倍 | 冒泡排序 |

**核心思想**：10 亿条数据，O(n) 要 10 亿步，O(log n) 只要约 30 步——**同一个问题，算法不同，天壤之别。** 所以「会选算法」和「不会选算法」的程序员，写出来的程序快慢能差出「1 秒」和「1 年」的距离。**选算法不是细节，是数学。**

## 2.8 计算的边界：有些问题永远算不出

算法再厉害，也有一道越不过的墙。**图灵机**（Turing，1936）把「计算」本身数学化了：

- 设想一台最简机器：一条纸带 + 一个读写头 + 几条规则——却能模拟**任何**可计算的算法。它是所有计算机的「理论原型」。

于是可以问一个深刻的问题：**有没有「数学上成立，但任何算法都永远算不出」的问题？** 有。图灵证明了**停机问题不可判定**——不存在一个程序，能判断「任意程序，最终会不会停」。

**这个结论的数学祖先，是康托尔的对角线论证**（1-02.4）：正是「无法编号的无穷」这种思路，证明了「有些问题没有算法」。**从「有些无穷数不完」，到「有些问题算不出」，中间用的是同一种推理。** 计算是有边界的，而这道边界，是用数学画出来的——这也为下一章（6-03 AI 的边界）埋下伏笔：**机器不是万能的，连「会不会停」都未必知道。**

## 误区（本局小结）

1. **「算法 = 代码」** —— 算法是「思路」，代码是「实现」。同一个算法可以用十种语言写。别把「背代码」当成「懂算法」。
2. **「更快 = 更复杂」** —— 恰恰常相反：二分搜索的代码比线性搜索还短，却快了几千万倍。「快」来自「好的思路」，不是「更多的代码」。
3. **「有最好的算法」** —— 没有。同一个问题，数据量、数据是否有序、内存大小不同，最好的算法也不同。只有「最合适」，没有「最好」。
4. **「递归会无限套下去」** —— 只要有「基线」（出口）就不会。递归的灵魂就是那个「不用再递归、直接给答案」的地基。
5. **「加密安全 = 锁够精巧」** —— 安全靠「拆锁够难」（质数难分解），不靠「锁的设计没人知道」。
6. **「计算机什么都能算」** —— 图灵证明「停机问题」不可判定：有些问题，任何算法都算不出。计算的边界，是数学。
